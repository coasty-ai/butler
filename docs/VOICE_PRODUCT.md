# Voice product contract

The subsequent Butler MVP specification narrows the user-facing product from the strategy PDF to the primary interaction: **hold a key → speak → release → watch the computer work**. Butler is the consumer app; CoArena is the intelligence/evaluation layer, and CoArena Gym packages reviewed workflows into environments and evaluations.

The app lives in the macOS menu bar. It shows a compact floating pill only while listening, working, paused, asking for approval, or briefly confirming completion. There is no dashboard, chat sidebar, model picker on the main surface, task builder, agent page, integration marketplace or prompt history on the main screen. Small settings and optional local review remain accessible through the tray. The browser page is an interactive preview, not the desktop's main screen.

## Interaction

1. Hold Option-Space. The native helper signals the controller's stop latch, emits the listening event and requests a haptic on supported hardware. The latch is lifted only for the one early step described under Data and measurement, and closed again right after it.
2. Start microphone capture and on-device streaming STT at key-down, so a quick “yes” is not clipped (a tap under 160 ms still opens text entry and discards the audio). Any reply the assistant is speaking stops first. Audio is never written to disk. Partial text is transient pill feedback. The recognizer is told the words a command turns on (Apple's contextual strings, at most 90 beside the wake phrase: the installed apps, the ones opened most, the ones open now, and Butler's own command words such as “TextEdit”, “Calculator”, “undo” and “scroll”), on the request a hands-free command continues from the wake phrase as well as on a push-to-talk one, so “quit Calculator” is not written “quick calculator”; the list is sent again when the installed apps change, and diagnostics record only its count.
3. Release. Capture continues for a 0.3 second tail, the pill shows “One moment…”, and final recognition is awaited for up to 1.8 seconds. Apple Speech segments that end while the key is held are kept and joined, not dropped. If the recognizer ends with an empty final marker, the latest nonempty hypothesis is kept as a recovered command. A hypothesis that never finalized is offered in the text pill as “Send this?” and never acts by itself. Recovered, merged and unconfirmed speech can never approve a pending consequential action.
4. Capture current screen context and begin the task. A known plan (a built-in intent or a learned skill) may run its steps first without model calls. Otherwise the model chooses one validated mouse/keyboard action, a launch-only `open_app` or an index-bound `open_file`, at a time.
5. Hold again to interrupt: the run pauses immediately. Final corrections revise the same run; stale in-flight responses cannot execute. “Wait” pauses; “Stop” cancels. These intents are read from the final transcript, not partials, so “Stop scrolling and click Save” stays a correction. A control verb with a thing for its object (“pause the video”, “stop the music”, “mute this”, “skip the ad”, “turn the volume down”) is a task on that thing, started at once in the user's words for the run to carry out on the screen, never Butler's own pause or stop, which the words mean only when they stand alone or refer to it or the task. Unrecognized speech keeps the run paused. Neither requires waiting for model inference. “Undo”, “undo that”, “take that back” or “revert that” (a final or a clearly heard recovered transcript, never a partial, and never an answer to an approval) presses Edit › Undo in the frontmost application through its own menu item: during a run the run pauses, undoes, says “Undone.” (or “Nothing to undo.” when the item is greyed out) and waits; within a minute after a run ended the same step runs as a short run of its own; later it is an ordinary request for the model; and it asks first only under the “ask” autonomy setting.
6. Consequential actions and labelled controls outside a benign allow-list show an approval; unidentified targets are retried without input. Click Yes or hold and say “yes.” Spoken approval must match the pending action from listening start and pass the final confidence gate. “Not yet” pauses the task.
7. The pill shows a short summary of the result (“Done.” when none is safe to show), then hides.

**Dictation.** When the words only ask to type text — “type hello world”, “dictate see you at six comma maybe seven”, “write ‘back in five’” — and a known text field has the focus in the frontmost app, the run types the words into it on its first screenshot and is done, with no model call. Spoken punctuation is written out (comma, period or full stop, question mark, exclamation mark, colon, semicolon, dash, hyphen, new line, new paragraph, open and close quote), each sentence starts with a capital, and names, “I” and numbers stay as the recognizer wrote them. The step goes through the same policy as a model step: typing into a known field is not a consequential action and never asked, so it runs whatever the autonomy setting; text with line breaks still asks where Enter may send (a chat) and runs unasked in a document editor (Notes, TextEdit). A password field, secure input, a terminal, a blind window and a protected app are refused or handed over exactly as for any other step, so nothing secret is ever typed this way. A destination (“write ‘see you at six’ in the note”, “type in Notes hello”), something to compose (“write an email to Dana”), a pointer (“type that again”), any mention of a password, or no focused field leaves the request to the normal run, with the words as they were said. The pill says “Typed it.”; the voice says only “Done.”, never the text.

**Scrolling.** “Scroll down”, “scroll up”, “scroll down slowly” or “keep scrolling” (a final, or a clearly heard recovered transcript, never an answer to an approval, never from the phone) scrolls the window in front gently until you say stop, with no model call: the native helper posts about two lines every 140 ms through the same wheel events a scroll step uses, on the window under the pointer (moved over the frontmost window first when it rests elsewhere), and checks the protected-surface floors about once a second, so it scrolls nothing a step could not. The pill says “Scrolling down… say stop.” and, in hands-free mode with follow-up listening on, a listening window stays open for the whole scroll (up to 95 s) that admits only steering words: “stop”, “stop scrolling”, “stop there”, “that’s enough” end it; “faster” doubles and “slower” halves the pace (between a quarter and four times); “scroll up” flips it; talk nearby does nothing. It also ends on any of your own mouse or keyboard input, when another window comes in front, and after 90 s without a word. A run under way pauses first and stays paused until “continue”; with nothing running, “stop” while scrolling stops only the scroll and leaves queued tasks and watches alone. Scrolling is read-only, so it asks nothing under any autonomy setting. “Scroll down a bit”, “scroll to the bottom” and “page down” stay single steps for the model, and “stop scrolling and click Save” stays a correction. Diagnostics record ScrollStarted (direction, lines per tick, tick) and ScrollEnded (reason: stop, input, appChanged, limit or error; ticks).

**Working in the background.** While you are at the Mac (Settings › Working, on by default), a task that names an application (“in Slack, tell Prateek I’m running late”), one whose first words opened an application, or one you gave while looking at a window binds that window and works in it without taking the screen: the run sees the window alone, acts through its accessibility controls first and then through events posted to that application, reads back after every step whether the window changed, and remembers per application which routes it ignores. The model is told so in one paragraph at the end of its instruction, present only on a bound run so the shared prefix stays cached. Your mouse and keyboard elsewhere are normal life; a click, a scroll or a key inside that window pauses the run (“Paused — you’re in Slack. I’ll continue when you switch away.”), which continues once that application is no longer in front and your last click, scroll or keystroke was somewhere else (moving the pointer over the window changes nothing either way), and Escape stops it as always. When the application ignores both routes, or a step has no background route (a drag, a chord that is no menu shortcut), the pill and the voice say “I need Slack for a second.”, the window comes in front for that one step and your application gets the front back; after three such seconds in ten steps the run finishes in front. The pill reads “Working in Slack in the background” over the last step (“clicked “Send””). When you are away from the Mac, after a watch woke the run, for an undo, and when the window cannot be bound (no window open, a protected app, a terminal), the run takes the screen as before. Off means every task takes the screen.

## Spoken replies

Butler answers out loud when you talk to it (Settings → Voice replies: Off, When I talk to it, Always). It speaks only at moments that need you or close a task: approvals (“Send this message? Say yes or no.”), questions from the model, clarifications (“Open what?”), pauses it caused, the result, and failures. Push-to-talk turns get a brief acknowledgement (“On it.”); hands-free turns get a soft sound instead, because the microphone stays open for a follow-up. It never speaks while the microphone is capturing, never reads typed text, credentials, coordinates, full web addresses or file paths, and never says a phrase that would itself stop, pause, resume, approve or decline.

- **Mac voice (default):** Apple `AVSpeechSynthesizer` inside the native voice helper, on-device and free, using the best installed voice. Compact voices sound robotic; Settings offers a shortcut to download a free Premium voice.
- **Natural voice (free, on-device):** Kokoro-82M (Apache-2.0) through ONNX Runtime in an Electron utility process, after a one-time 332 MB download (pinned revisions, SHA-256 verified) from Hugging Face and GitHub. Nothing you say or type leaves the Mac. Pronunciation uses the misaki gold dictionary plus a small non-espeak fallback model, so no GPL code ships. The worker starts on first use or when you start talking, takes about 1.3 s to its first audio when cold and about 0.5 s per short sentence when warm, uses about 700 MB while loaded and exits after 5 minutes idle. Apple Silicon only; any failure before audio starts falls back to the Mac voice.
- **Natural voice (OpenAI, opt-in):** `gpt-4o-mini-tts` streamed as PCM from the main process to the helper. Allowed only with the Bring-your-own-model privacy mode and an OpenAI key. The reply text goes to OpenAI, it costs about $0.015 per spoken minute on your key, and the voice is AI-generated. Any failure before audio starts falls back to the Mac voice.
- **Interrupting:** holding Option-Space, the wake phrase, Escape, a click on the pill, Stop or Control-Option-Escape stops speech immediately inside the helper, before the app handles the event. In hands-free mode, listening pauses while the assistant speaks and for 0.8 seconds afterwards (1.2 s on Bluetooth output), so its own voice is not transcribed. With echo cancellation on the microphone (the helper's voice processing, a local trial flag until the cancellation is measured: `BUTLER_FULL_DUPLEX=1` in the helper's environment; the natural voice and the earcons then play through the same audio engine as the microphone, which is what the cancellation subtracts), listening continues while the natural voice speaks: “stop”, “wait”, “hold on” or “no” said over a reply silences it at once, the wake phrase interrupts it as usual, and an open conversation-mode window takes plain words as it does between replies. Whatever the cancellation lets through of Butler's own sentence (its words, in order, or a part of them) is dropped as its echo and never becomes a command; the owner's words, the wake phrase and the reply words a bare answer or control word repeats are not. The Mac voice plays outside that engine, so its replies keep the pause. The processed microphone arrives as several channels; the helper reads the one carrying the room, and if what it gets is silence for three seconds it goes back to pausing on its own rather than stay deaf. Settings › Talk to Butler says which applies.

## Forgiving turn-taking

Hands-free turns end on several signals instead of a fixed pause. A turn ends when the words have stopped changing and the microphone has been quiet for long enough, and how long depends on whether the sentence sounds finished. With the default Normal patience: 2.0 s of stable words and 1.5 s of quiet for a finished-sounding command; 3.5 s and 2.5 s when it ends on a word like “and”, “to”, “can you”, “um” or a lone verb such as “Open”; 0.9 s and 0.7 s for “stop” or a short answer. Quick and Relaxed patience scale these (Settings → Listening). Quiet is measured against an adaptive noise floor, so soft trailing words still count as speech. Apple's recognizer segments are accumulated, so words before a long pause are not lost; stutters, fillers (“um”, “uh”) and repeated words are removed before the command reaches the model, and misheard wake echoes (“Hey sis”, “Hey assistant”) are stripped. Saying the wake phrase again part-way (“Assist, open Calendar and…”) starts the request over: only the words after the last wake phrase are the command. At the start of a new recognizer segment it is the wake phrase as it activates from standby, “Hey Butler” or the bare name behind the same gate (“Butler open…”, “Butler, …”, “Butler stop”, “Butler, is Slack open”; not “Butler in the UK…”, “the butler…”, and never the misheard echoes such as “Hey sir” or “I say”, which are ordinary speech there). One gate for waking and restarting means dictation that opens a new segment with the name and a gate word (“Butler is off today”) restarts too; the fixture's restart list pins that cost rather than a second, narrower rule. Inside one segment it is “hey butler”, or the bare name when the request's opening words repeat after it. A restarted turn counts as more than one segment, so it can never approve.

A lone fragment such as “Open” gets a question (“Open what?”) instead of starting a run. With follow-up listening on, the assistant keeps listening without the wake phrase after a turn (to catch “…and search”), after it asks a question and after an approval prompt; how long is the “Keep listening” choice below. Words added before the run has acted amend the task instead of counting as a correction.

**Keep listening (Settings → Talk to Butler).** How long those windows stay open is a choice, sent to the helper with the other listening settings and decided in one table on both sides (`followUpSeconds` in TurnPolicy.swift and src/voice/turns.ts). _Conversation_ is the default: “Hey Butler” activates the listening and the listening does not stop until thanks. After the wake phrase, and after every reply, answer and approval prompt, the window stays open with no timer of its own, reopened after each turn (heard or not: “Hey Butler” alone opens it, and one missed word does not end it) and after each reply (listening pauses while Butler speaks, so a reply closes the window; one that asks nothing, a result, “Stopped.”, a progress line, reopens it as it ends, and one that asks a question opens its own: `conversationWindowAfter` in TurnPolicy.swift), so a person can keep talking to Butler without repeating the wake phrase, and in that window anything anyone says in the room is taken as addressed to Butler (the setting’s hint says so). The helper keeps the window alive across its own recognition requests (a fresh request every 40 s of quiet, hearing the ring’s last moments first, as a scroll’s window does). The one timer is an inactivity cap, the reason an empty room cannot keep issuing commands: after 15 minutes with nothing addressed to Butler (`conversationIdleSeconds`, renewed by every turn and reply) the window closes silently and the wake phrase is needed again. Speech still has to be speech: the 0.24 s onset detection (of speech heard within the last 2.5 s, `speechRunRecentSeconds`: a word the recognizer writes later, with no energy behind it, opens no turn however long the window has been open), the wait on a lone “Hey” and on a lone “Hey Butler” or “Butler” (which then wakes with the window’s context after its pause, instead of counting as the reply’s first word), the pause while Butler speaks and for the echo guard after it, the secure-input pause and the close on sleep, screen lock or hands-free turned off are unchanged, and a window never widens what a spoken “yes” may approve (an approval prompt listens 12 seconds in this mode too, with the stricter follow-up checks; when they pass unanswered the window goes on as a continuation window, so the question stays on the pill, the conversation stays open, and a later “yes” is heard with those checks). “Thanks”, “thank you”, “thanks a lot”, “thank you Butler”, “that’s all”, “that’ll be all”, “that’s it”, “stop listening”, “goodbye” or “good night”, said on their own, end the window without doing anything else: the helper plays its soft sound and opens no window after them, and the app shows “Okay. Say “Hey Butler” when you need me.” and runs, resumes and approves nothing for them. Inside a longer command they are ordinary words (“thanks, now open Notes” continues; “write thank you in the note” is a dictation), and a bare thanks while an approval is pending is the acknowledgement it always was: the question is asked again and stays open, and since the helper heard only a closing phrase and opened no window after it, the app asks it for a continuation window, so the room stays open for the answer with replies off and after the second re-ask too. _Briefly_ keeps the windows 3 seconds after a turn and 8 seconds after a question or an approval prompt; _Longer_ 20 seconds after a turn or a question and 12 seconds after an approval prompt, with the same rules for what counts: a continuation still has to sound like one (“and…”, “actually…”), an answer can be anything. A saved Longer stays, and so does a Briefly picked in Settings (`followUpWindowChosen`); the Briefly every earlier build wrote into the config on its own as the old default moves to Conversation once at launch (`migrateFollowUpWindow`), and a config without the setting takes the default. The pill glows and the menu-bar tooltip says “Listening, no wake phrase needed” while a long window is open. A click on Yes or No and the end of a scroll still close the window for good (the app ends it, as under every setting), so the wake phrase is needed after them unless the reply that follows asks a question. Whether an open conversation picks up the owner’s other conversations as commands, and how a 15-minute window feels in a shared room, is not something the fixtures can settle; only a live trial can.

A spoken approval inside a follow-up window needs higher recognition confidence, a single recognizer segment and the same pending action, and it only covers low-risk prompts: opening an app or file, quitting an app, and navigation clicks such as “Next page” or “Learn more”. Anything that sends, submits, changes settings, deletes or installs needs a click, push-to-talk or the wake phrase, unless the asking setting is “Only when it cannot be undone” or an acknowledged “Never ask, allow everything”: then a clearly heard “yes” answers any question. “Never ask, allow everything” also removes every question itself (every step is reported instead); only the question before a protected website remains, and refusals never change.

A short tap opens text entry; Command-Shift-Space provides a fallback. Escape and Control-Option-Escape are native stop controls during real runs. Escape also cancels ongoing speech. Manual mouse/keyboard input pauses the run instantly (pointer jitter under 3 px is ignored). It continues on its own from a fresh observation once the user lets go: about a second after pointer movement or scrolling, three seconds after clicks or typing, unless anything else happened meanwhile. “Continue” still resumes at any time. When the agent cannot identify a control it asks the user to click it, and continues a second after that click. Dismissing an untouched text-entry pill opened by a tap during a working run resumes it; other dismissals leave a held run paused. With hands-free mode off, voice steering requires holding the shortcut. With optional “Hey Butler” enabled, the native helper listens locally for the wake phrase at the start of an utterance, “Hey Butler” or just “Butler” (the “Hey” is optional, never required), plays a soft sound, opens the same pill, and ends the turn with the patience rules above. Either way the name must be followed by a pause, a task verb, a control word (“stop”, “yes”), a reply or greeting (“sure”, “thanks”, “good morning”), a lead-in (“actually”, “so”, “just”) or a question word (“what”, “can”, “is”, “do”, “anything”), since the recognizer writes no punctuation; “Hey Butler's on the phone”, “Butlers are rare these days”, “the butler did it” and “my butler is late” stay asleep, and a lone “Butler” waits for the pause as a lone “Hey Butler” does. The bare name buys false accepts the gate cannot refuse, listed in the shared fixture (“falseAccepts”) rather than denied: a sentence about a butler, the surname or the town that opens with the word and goes on with a pause or a gate word (“Butler, come here”, “Butler is late”, “Butler did it”, “Butler was here”, “Butler, Pennsylvania”) wakes it, exactly as “Hey Butler is late” would; the gate still refuses the name inside a sentence, a possessive or plural, and the name before an ordinary word (“Butler the weather”). Two seams also put the word at an utterance start without anyone addressing Butler, where before they needed “Hey” and the name after them: a breath of 0.6 s before the noun (“we hired a … butler.”) begins a new utterance at the word, and the lone “butler” then wakes on the final or after its pause; and the cadence rotation of a long hypothesis begins a fresh one on the last 1.5 s of the room's sound, so a sentence that ended in “…butler” just before it is heard as the word alone, and the quiet that triggered the rotation is the pause the lone name waits for. Whether Apple's recognizer writes the bare name reliably at an utterance start without the “Hey” lead-in, and how often those seams wake it, is for a live run to show: the speech study heard Butler as “Batala” and “but a lot” for some voices, and the recognizer is now biased toward both “Hey Butler” and “Butler”. The standby trace (BUTLER_TRACE_STANDBY) records each wake's utterance boundary and each rotation, and the first three words of any utterance that opens with the lead or the name, so the trial can count the wakes whose utterance began at a seam and read what the recognizer wrote for the name without logging the room. While Butler speaks under full duplex, its own reply heard back as far as the name (“I'm Butler…”, “Butler is ready…”) is its echo, dropped and never a wake phrase waiting for its pause; the owner's words after the name (“Butler stop”, “Butler, open Notes”) are not in the reply and are the owner's. While people talk nearby, Apple's recognizer keeps one hypothesis running through the conversation; words that arrive after the text has stood still for 0.6 s begin a new utterance, so “Hey Butler” said after a breath is heard there too, and the room's words before it are never part of the command. A wake phrase said in one breath inside a sentence still never activates. The command window times out after ten seconds without words (Normal) and ends at 45 seconds. A nonempty final recognition normally supplies the command. An empty final after the explicit silence/release endpoint may recover the latest nonempty hypothesis; when that hypothesis had stood unchanged for 1.5 s it counts as clearly heard for starting or steering a task, but it is marked separately and can never approve an action. Outside a follow-up window, say the wake phrase again for corrections, stopping and approval. Ambient speech outside a window cannot act, and follow-up approvals carry the stricter checks above. The microphone remains active until disabled in the menu bar or the app quits. Existing settings migrate with this mode off.

## Data and measurement

Local encrypted records connect intent → action → finalized correction → revised action → outcome through one run ID and action index. Correction timestamps remain local. Per-run opt-in contribution can include sanitized task/action/correction text; raw audio is never included, and real desktop screenshots are excluded until image sanitization is implemented and validated. There is no default telemetry upload.

The proposed north-star metric is the number/share of active users initiating at least five real tasks from the shortcut per local day. Count a new task once; exclude tutorials, retries within a run, approval utterances and correction utterances. Track correction success, task completion and time to first useful action alongside it. Central collection and a users/day report are not implemented; they require a separate opt-in measurement design.

The <100 ms listening-feedback target is a target, not a measured result. Measure key-down→visible pill, key-down→audio-ready, release→final transcript, release→first action, and interrupt→last emitted input at p50/p95 on target Macs. Avoid speculative input before the user finishes speaking, with one exception (Settings → Listening → “Open apps as I say them”, on by default): when a request starts with “open”, “launch”, “go to”, “take me to”, “show me”, “switch to”, “pull up” or “bring up” and names a place, the assistant is already going there before the sentence ends. An installed app is brought forward; a website (“youtube”, “github dot com”, “github.com”, a dozen well-known names such as gmail, google docs, reddit and wikipedia) brings forward the browser the page will load in; a standard folder (“downloads”, “my desktop”, “the documents folder”) opens in Finder. It acts the moment the words name one place (an installed app's exact name or the one installed name they begin with, an address with its ending, a known site or folder), unless the words could still go on to name another (“google” may become “google docs” or “Google Chrome”, “the downloads” a page): then it waits for a following “and”, “then” or comma heard twice or held for 0.3 s, or for the words to stop for 0.6 s. Only verified, non-protected apps and folders inside the home folder open (never the home folder itself, the Trash or /Applications); nothing is typed, clicked or sent early, and no address is entered until the final transcript, which the run then loads as a known plan without a model call. A change of mind (“or”, “no”, “actually”, “in Chrome”, “Slack's…”) cancels it for the turn, nothing is spoken about it, and an app brought forward is never switched away again. The final transcript decides whether the run keeps the step: “open Visual…” that brought Visual Studio Code forward is kept when the sentence ends “…Studio Code” and dropped, with the run correcting course, when it ends “…Paradigm”. The fast-start line “Opening Slack.” is then replaced by the plain acknowledgement. The optional hands-free implementation uses rolling Apple on-device recognition, not a dedicated low-power wake-word model; wake latency, false activations and battery impact still require microphone testing.

No proactive assistant, schedules, mobile app or integration platform is part of this MVP. Bounded current/recent context is included: app/window title, selection/static accessibility text, up to 12 open/recently observed windows, eight observed document basenames and the last three local tasks. Local learned memory adds relevant past episodes, corrections, apps, folders and Spotlight-listed files, and replays predictable procedures ([MEMORY.md](MEMORY.md)). It is not a continuous screen recorder, and it never reads file contents. Spoken replies, including the free on-device natural voice, are described above.
