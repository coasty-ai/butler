# Architecture inventory and implementation boundary

The initial `/Users/nkov/open-assist` repository contained only the 39-page strategy PDF and Git metadata. No existing desktop framework, capture layer, executor, provider integration or agent loop was present. The nearby `coasty-local-agent` was inspected read-only: it is a small Python/mss/PyAutoGUI example using a stateful Coasty API, not the multi-provider Open Cowork application described in the report. No existing application was rewritten or changed.

This repository implements a macOS-first desktop alpha: an Electron menu-bar application with separate pill and settings renderers, a TypeScript state machine, independent Swift speech and computer-control processes, encrypted append-only history, opt-in contribution tools and a synthetic Gym starter. The renderer has no Node or arbitrary IPC access. Provider requests originate in the main process. The model has no shell, filesystem, DOM or application API tools. Bounded accessibility text is observation data, not a callable full-tree inspection tool.

The native voice process owns Option-Space key-down/up. Key-down latches the controller via SIGUSR1 before JS handles the event and requests haptic feedback on supported hardware. A 160 ms hold starts microphone capture and on-device streaming recognition; a tap opens text input. Release stops audio and waits for a final recognition result, up to 1.8 seconds. Partial transcripts update the pill. An empty terminal result after release/the silence endpoint preserves the latest nonempty hypothesis as a recovered command, with zero approval confidence. A finalized correction stays in the same run; an epoch check discards late model responses. Approval requires a matching pending action and sufficient final speech confidence, or a click. Audio and the stream of partial transcripts are never persisted; recovered commands enter history only when submitted.

The native process owns an emergency-stop/manual-input event tap and checks its own stop latch during input. Its event loop remains independent of provider requests and the renderer. All generated events carry a marker; unmarked mouse/keyboard input pauses the run, and Escape cancels. Manual input content is not recorded. Capture and input remain disabled until OS permission is granted. Unsupported operating systems fail explicitly; the tutorial remains usable.

Private-local mode permits only literal loopback inference endpoints, rejects redirects and disallows cloud model identifiers. Private BYOM routes content directly to a user-configured provider. Telemetry is disabled; an allow-listed schema is available for a future opt-in sender. Sponsored routing is not enabled without a separately reviewed service.

Local AX hit-testing identifies a small allow-list of editable and preparation/navigation controls. Unknown controls and consequential actions require approval. Protected applications, detected secure inputs and sensitive domains require takeover before capture. Safety metadata remains local. Separately, observations include bounded window titles, static accessibility text and selected text, plus recent window/document/task references as requested by the updated MVP specification. Credentials detected in this context are omitted before provider requests. User approval is tied to a frame; changed geometry, application or screenshot forces replanning. This classifier is intentionally limited and is not a general guarantee of semantic safety.

The tutorial is a deterministic in-app simulation, clearly labeled. It exercises the same action schema, run loop, journal and contribution flow, but is not evidence that a model can operate the host desktop.

Contributions have a separate endpoint and explicit per-run review. Raw native screenshots are excluded from contribution in this alpha: OCR alone is not a sufficient privacy guarantee. Statistics and sanitized text/action metadata are supported. Synthetic tutorial frames can be included. A reference encrypted ingest service implements consent, checksums, resume, commit and deletion. It is for local development; production requires authenticated deployment, storage/KMS, retention operations and privacy review.
