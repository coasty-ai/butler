# Developer guide

## Add a provider

Implement `Provider.next(observation, signal)` and return one provider-neutral action plus usage. Update configuration validation and provider UI. Send only the screenshot, objective, compact action history and validated bounded screen context. Do not send OS safety metadata, provider credentials in content, or hidden reasoning. Treat titles/selection/history as untrusted data. Refuse redirects and propagate cancellation. Add representative response, malformed-call and network tests. Vendor-native computer-use tools should translate into the same schema and preserve provider safety checks; do not skip the local policy engine.

The Mac app uses `createDesktopProvider` and Chromium networking in a separate, in-memory session with cookies omitted and cache disabled. This honors system network/proxy settings without sharing renderer sessions. After `ERR_SSL_BAD_RECORD_MAC_ALERT`, pooled connections are discarded. If Chromium resolves the route as exactly `DIRECT`, the next bounded retry uses Node's verified TLS transport at the same endpoint; configured system proxies are never bypassed. Transport errors expose only allow-listed codes. Recognized connection interruptions (including failed TLS records) and HTTP 429/5xx get at most two retries; certificate, credential, DNS and malformed-response errors do not. A single 60-second deadline includes retries and response consumption. Stop cancels requests and retry backoff. Retrying inference never replays computer input; an inference whose response was lost may still be billed, so unreported usage is not included in the local cost estimate.

For supervised live debugging use `npm run debug:local`. It launches the packaged app through macOS LaunchServices with diagnostic environment variables and follows `.data/diagnostics/current.jsonl`. Do not spawn the application executable directly for interactive voice testing: TCC may attribute Speech Recognition to the parent editor/terminal, causing a privacy-usage-description crash even though Open Assist's own plist is correct. Playwright integration checks do not establish permission attribution for interactive speech. The stream is local, opt-in, allow-listed, redacted, mode 0600 and capped at four 5 MB files. It records no screenshots, task/transcript text or typed text. Full local trajectories retain their existing encrypted storage.

`npm run test:provider -- openai --desktop` is an opt-in paid API test using the packaged Electron runtime, the production provider factory, generated browser screenshots and isolated app storage. It includes a 15-second idle gap like an approval wait. It never captures the desktop or sends OS input. Build/package first, provide an explicit local `.env`, and optionally set `PLAYWRIGHT_CHROMIUM_EXECUTABLE`. Without `--desktop`, this check tests Node's transport only. Neither mode establishes arbitrary-app reliability.

## Add an OS backend

Implement `Controller`: surface safety metadata, capture with exact geometry and monotonic timestamp, bounded context, validated input, stop, resume and optional foreground restoration. Keep emergency stop and manual-input detection in a native event loop independent of renderer/provider work. Tag generated input so it cannot trigger voice recording or manual takeover. Re-check actual display/window geometry and freshness immediately before actuation. Unsupported capabilities must fail closed. Only validated, bounded accessibility text belongs in model observations; safety metadata and arbitrary AX access remain local.

The Swift helper uses newline-delimited JSON on private stdin/stdout. Requests have an ID and an allow-listed method; outputs have the same ID plus result/error. The main process owns it and closes it on exit. A SIGUSR1 stop latch and native key event tap interrupt input independently of request completion. No native logs contain screenshot text.

Screen hashes identify stored images; they are not GUI stability checks. Native revalidation binds input to the original process, focused window, document, display geometry and observation age. A bounded accessibility snapshot checks control labels, complete-value digests, enabled state and geometry. Known stable controls may animate focus/hover/carets, but pointer targets must still hit the original element or its descendant. Elsewhere, rendered-pixel comparisons check the active window and stricter click/drag target regions. This is a heuristic with incomplete accessibility coverage, not proof against all adversarial UI changes.

Native `STATE_CHANGED` errors cause a fresh observation and proposal; they never replay an old action. Three consecutive changes pause the run until the user resumes. Approval uses the same native revalidation; a material change expires approval and requires a new one. Display geometry is stored as explicit `Double` values to avoid failed `CGFloat` casts inside the native process.

The runner compares geometry keys and values independently of JSON property order. Swift dictionary serialization order changes between captures; treating the serialized strings as geometry identity incorrectly invalidated successful native approvals. Missing, additional or changed geometry fields still invalidate approval.

`npm run test:native-safety` tests the pixel comparator. `npm run test:native-input` opens a disposable opaque AppKit window and uses the real controller to click/type while a clock and caret animate, then verifies that moved/relabelled controls, changed field values/focus and a different window block input. It sends no model requests and saves no screenshots. Build the native helpers first; add `-- --packaged` to exercise the packaged helper.

The input event tap ignores a mouse-moved notification only when both its position and hardware deltas are unchanged. Actual position changes (including fractional movement), nonzero movement at screen edges, keys, clicks, scrolling and dragging still pause immediately. The native fixture verifies both a stationary event and real movement. Voice invocation now remembers the foreground application before displaying the pill. Resume hides the pill and restores the captured target, falling back to the remembered application when no external target has yet been captured. Focus restoration does not bypass fresh-screen checks.

## Add a safety rule

Change `surfacePolicy` for pre-capture rules and `evaluate` for proposed actions. Native guard checks are an independent layer. `DENY` must not journal the secret-bearing proposal; only its reason/code. `USER_TAKEOVER` suspends capture and input until explicit Resume. Approval never bypasses fresh-screen/geometry checks. Do not rely on a model-provided risk label.

## Local data schema

`Run`: UUID, local task, privacy/provider/model, lifecycle state, action/frame counts, token/cost totals, user outcome. `JournalEvent`: event UUID, run UUID, sequence, monotonic/wall timestamps, schema version, type and structured payload. `Frame`: ID/hash, encrypted image reference/data, exact native/model geometry, capture time and synthetic flag. `Action`: strict union of the small GUI vocabulary tied to `frame_id`.

Finalized steering records `UserCorrectionRecorded` with text, action index and local timestamp on the same run. A trajectory contribution contains sanitized correction text and action index; a statistics contribution omits correction text. Audio and the stream of partial STT output never enter the recorder. A hypothesis recovered at the explicit end of an utterance is recorded only as the submitted command/correction. The separate Swift speech process requires on-device recognition and handles key-down/up independent of inference. Keep pending-action binding and final-only approval when changing voice routing.

Events are individually GCM authenticated with run ID, sequence and previous ciphertext hash as associated data. Frame ciphertext is content addressed within each run. Repeated identical captures share content; `FrameCaptured` events retain each capture's ID/hash/geometry for reconstruction. Incomplete final journal writes are removed during recovery; completed authenticated records are retained. Interrupted runs become failed and are never automatically replayed.

A `Bundle` contains only consented statistics or sanitized task/action fields and synthetic tutorial images. It omits raw local paths, app titles, URL metadata, API keys and provider response bodies. Consent binds a policy version, run ID, timestamp, data classes, purpose, retention and complete bundle hash. The encrypted local approved copy is the sole source for Gym export.

## Checks and operations

- `npm test`: pure unit/integration tests; no paid inference or desktop input.
- `npm run test:e2e`: browser preview UI, tutorial, review/cancel, deletion and responsive layout. Install Chromium first, or set `PLAYWRIGHT_CHROMIUM_EXECUTABLE` to an existing executable.
- `npm run test:desktop`: actual Electron/Keychain/HTTP contribution integration using only synthetic data; no microphone or host input.
- `npm run build:native`: compile both Swift helpers for the current Mac architecture.
- `npm run build`: type check and bundle renderer/main/preload.
- `npm audit`: review the lockfile dependency tree.

The native permission/actuation matrix and live providers require dedicated manual/sandbox fixtures and credentials. Keep those test results separate from scripted tutorial results. `output/qa/` contains UI QA screenshots from the current work session.

## Optional hands-free voice

The saved `handsFree` setting defaults to false, including legacy encrypted configurations. Enabling it configures the native voice helper; the menu-bar toggle can disable capture even during a run. `WakePolicy.swift` anchors “Hey Assist” / “Hey Open Assist” at utterance start and determines silence/empty-command timeouts. `Voice.swift` retains background transcription inside the helper and emits neither text nor levels until activation. Each recognition generation invalidates stale callbacks on cancel, mute, restart and sleep. Standby sessions rotate at 45 seconds; nonempty final recognition normally supplies the command; an empty final after the explicit endpoint preserves the latest nonempty hypothesis as a separately marked recovered command. Wake detection signals the same native stop latch as push-to-talk and binds the same pending approval. macOS permission descriptions cover the optional always-active microphone. Diagnostics add only wake-state booleans/events; no ambient text or audio.

This local implementation reuses Apple Speech with `supportsOnDeviceRecognition` checked and `requiresOnDeviceRecognition` set. It has no backend, added speech API charges, custom wake model, or speaker verification. Apple reference: https://developer.apple.com/documentation/speech/sfspeechrecognizer/supportsondevicerecognition. Dedicated low-power keyword detection and measured false-wake/battery testing remain follow-ups.

Routine navigation policy: Escape, exact Command-Space / Command-Tab / Command-Shift-Tab / Command-F combinations, browser-specific Command-L, verified text selection/editing, tabs/menus, and Enter in a verified Spotlight text field can proceed automatically. Unknown targets and arbitrary navigation shortcuts trigger bounded recovery before takeover; message-field Enter, potentially destructive shortcuts and consequential controls still require confirmation. Protected surfaces and credential/clipboard restrictions precede these rules. Policy decision reasons are included in the local diagnostic stream.

Local task replay: `npm run debug:local -- --hands-free --command "Open Notes"` submits through the same command, policy, budget and cancellation paths as voice. It uses LaunchServices to preserve microphone permission attribution. An already running instance receives the command without opening Settings. Task text remains in the encrypted run journal, not the diagnostic stream.

Each model observation carries the exact successful action arguments (without obsolete frame IDs) and the current macOS app identifier. Single-key hotkeys normalize to ordinary keys before policy evaluation. The native controller identifies Spotlight only when its search panel is visibly present and its accessibility text field owns focus. Captures wait up to 250 ms for the app to process the preceding generated input; cancellation stays active. A one-use, 150 ms exception recognizes only the matching Command-Space event forwarded by the system Siri executable. Physical input, other keys/modifiers, other processes and expired events still trigger takeover.

Spotlight Enter is permitted only when the AX-selected result exactly matches the nonempty query (case and `.app` suffix normalized); installer/destructive selections are rejected. The model receives `context.launcher.query` and `selectedResult`. Selected-result changes invalidate the native frame. Uninstaller processes require manual takeover before capture or input. Pointer targets labelled Uninstall are denied. This guard does not establish general semantic task correctness.

Second-instance launches transmit original argument pairs with Electron `additionalData`; Chromium-reordered argv must not be used to extract a command. The packaged desktop test submits Stop from a real second process and verifies cancellation with no task correction. Reference: https://www.electronjs.org/docs/latest/api/app#event-second-instance.

Navigation/input revalidation: OS navigation and browser-specific Command-L verify the original window, display, protected-surface state and stop latch without requiring unrelated content pixels to freeze. Text editing verifies the exact focused AX element, role, label, value, selection range, enabled state and bounds. Browser-address Enter requires a native toolbar field outside any AXWebArea; form-field Enter keeps confirmation. Browser address text is bounded/redacted in model context and omitted from plain diagnostic logs. Executable/local-file address schemes are rejected. Verified playback controls and public YouTube watch/results links are routine navigation. Unknown clicks trigger bounded recovery without execution; consequential actions retain approval and full revalidation.

A browser-only Command-L proposed in a non-browser application is rejected with switch-app guidance, rather than asking the user to approve an unrelated shortcut. Successful execution resets the consecutive invalid/denied-action counter; cost/time/action budgets still bound the whole run.

Unidentified target recovery: the policy returns `RETRY` for an unrecognized click or navigation shortcut. The runner sends no input, records `ActionRetargetRequested`, and gives the model fresh context plus a different-route instruction. Three consecutive targeting failures pause for manual help, with no generic approval popup. Successful input resets the retry count. Consequential controls and potentially submitting/deleting keys still use scoped confirmation. Diagnostic events include action type, foreground app and AX roles, never control labels or field contents.

Dock application clicks require native hit-test ownership by `com.apple.dock`, `AXApplicationDockItem`, and a file URL resolving to an application bundle identifier. Document/Trash items, installers and protected applications do not inherit this permission. Apple Notes supports exact Command-N and multiline typing/Enter in its document text area; message composers do not inherit Notes-specific permissions. Focusing a text field is classified separately from activating a Send/Delete button.

GPT-5.4 mini requests now explicitly use `reasoning.effort: low` and a 4,096 output-token ceiling; other model IDs retain their previous request shape. This keeps the selected model and allows recovery from rejected actions, while reasoning tokens count toward cost. OpenAI documents `none` as the mini default and `low` as supported: https://developers.openai.com/api/docs/models/gpt-5.4-mini . This configuration is not a guarantee of better task completion.
