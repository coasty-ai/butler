# Developer guide

## Add a provider

Implement `Provider.next(observation, signal)` and return one provider-neutral action plus usage. Update configuration validation and provider UI. Send only the screenshot, objective, compact action history and validated bounded screen context. Do not send OS safety metadata, provider credentials in content, or hidden reasoning. Treat titles/selection/history as untrusted data. Refuse redirects and propagate cancellation. Add representative response, malformed-call and network tests. Vendor-native computer-use tools should translate into the same schema and preserve provider safety checks; do not skip the local policy engine.

The Mac app uses `createDesktopProvider` and Chromium networking in a separate, in-memory session with cookies omitted and cache disabled. This honors system network/proxy settings without sharing renderer sessions. After `ERR_SSL_BAD_RECORD_MAC_ALERT`, pooled connections are discarded. If Chromium resolves the route as exactly `DIRECT`, the next bounded retry uses Node's verified TLS transport at the same endpoint; configured system proxies are never bypassed. Transport errors expose only allow-listed codes. Recognized connection interruptions (including failed TLS records) and HTTP 429/5xx get at most two retries; certificate, credential, DNS and malformed-response errors do not. A single 60-second deadline includes retries and response consumption. Stop cancels requests and retry backoff. Retrying inference never replays computer input; an inference whose response was lost may still be billed, so unreported usage is not included in the local cost estimate.

For supervised live debugging use `npm run debug:local`. It launches the packaged app through macOS LaunchServices with diagnostic environment variables and follows `.data/diagnostics/current.jsonl`. Do not spawn the application executable directly for interactive voice testing: TCC may attribute Speech Recognition to the parent editor/terminal, causing a privacy-usage-description crash even though Butler's own plist is correct. Playwright integration checks do not establish permission attribution for interactive speech. The stream is local, opt-in, allow-listed, redacted, mode 0600 and capped at four 5 MB files. By default it records no screenshots, task/transcript text or typed text; `COARENA_DIAGNOSTICS_VERBOSE=1` (`npm run debug:local -- --verbose`) is the separate opt-in that does record them, for a debugging session only, and `scripts/voice-loop.mjs` requires it. Full local trajectories retain their existing encrypted storage. The table below says what each journal event's row carries.

## Add an OS backend

Implement `Controller`: surface safety metadata, capture with exact geometry and monotonic timestamp, bounded context, validated input, stop, resume and optional foreground restoration. Keep emergency stop and manual-input detection in a native event loop independent of renderer/provider work. Tag generated input so it cannot trigger voice recording or manual takeover. Re-check actual display/window geometry and freshness immediately before actuation. Unsupported capabilities must fail closed. Only validated, bounded accessibility text belongs in model observations; safety metadata and arbitrary AX access remain local.

The Swift helper uses newline-delimited JSON on private stdin/stdout. Requests have an ID and an allow-listed method; outputs have the same ID plus result/error. The main process owns it and closes it on exit. A SIGUSR1 stop latch and native key event tap interrupt input independently of request completion. No native logs contain screenshot text.

Screen hashes identify stored images; they are not GUI stability checks. Native revalidation binds input to the original process, focused window, document, display geometry and observation age. A bounded accessibility snapshot checks control labels, complete-value digests, enabled state and geometry. Known stable controls may animate focus/hover/carets, but pointer targets must still hit the original element or its descendant. Elsewhere, rendered-pixel comparisons check the active window and stricter click/drag target regions. This is a heuristic with incomplete accessibility coverage, not proof against all adversarial UI changes.

Native `STATE_CHANGED` errors cause a fresh observation and proposal; they never replay an old action. Each carries the kind of change as a fixed code (`change`: `FOCUS_CHANGED`, `WINDOW_CHANGED`, `APP_CHANGED`, `CONTROLS_CHANGED`, `PIXELS_CHANGED`, `TARGET_COVERED`, `DISPLAY_CHANGED`, `STALE_FRAME`, `FRAME_EXPIRED`, `MENU_CHANGED`; `screenChangeCodes` in `native/macos/FrameSafety.swift`, pinned by `tests/fixtures/screen-changes.json`), which `ActionFailed` records and the model's rejected-step entry names; a hotkey refused because focus moved is told to wait for focus to settle (a published chord already goes through its menu item unless the step was approved; the ones refused for focus are kept as keys on purpose or were approved, so the model is never pointed at `menu_item` for them). Three consecutive changes pause the run until the user resumes. Approval uses the same native revalidation; a material change expires approval and requires a new one. Display geometry is stored as explicit `Double` values to avoid failed `CGFloat` casts inside the native process.

Focus restoration does not bypass fresh-screen checks.

## Add a safety rule

Change `surfacePolicy` for pre-capture rules and `evaluate` for proposed actions. Native guard checks are an independent layer. `DENY` must not journal the secret-bearing proposal; only its reason/code. `USER_TAKEOVER` suspends capture and input until explicit Resume. Approval never bypasses fresh-screen/geometry checks. Do not rely on a model-provided risk label.

## Local data schema

`Run`: UUID, local task, privacy/provider/model, lifecycle state, action/frame counts, token/cost totals, user outcome. `JournalEvent`: event UUID, run UUID, sequence, monotonic/wall timestamps, schema version, type and structured payload. `Frame`: ID/hash, encrypted image reference/data, exact native/model geometry, capture time and synthetic flag. `Action`: strict union of the small GUI vocabulary tied to `frame_id`.

Finalized steering records `UserCorrectionRecorded` with text, action index and local timestamp on the same run (the diagnostics row carries the text's length and the action index only). A trajectory contribution contains sanitized correction text and action index; a statistics contribution omits correction text. Audio and the stream of partial STT output never enter the recorder. A hypothesis recovered at the explicit end of an utterance is recorded only as the submitted command/correction. The separate Swift speech process requires on-device recognition and handles key-down/up independent of inference. Keep pending-action binding and final-only approval when changing voice routing.

Events are individually GCM authenticated with run ID, sequence and previous ciphertext hash as associated data. Frame ciphertext is content addressed within each run. Repeated identical captures share content; `FrameCaptured` events retain each capture's ID/hash/geometry for reconstruction. Incomplete final journal writes are removed during recovery; completed authenticated records are retained. Interrupted runs become failed and are never automatically replayed.

A `Bundle` contains only consented statistics or sanitized task/action fields and synthetic tutorial images. It omits raw local paths, app titles, URL metadata, API keys and provider response bodies. Consent binds a policy version, run ID, timestamp, data classes, purpose, retention and complete bundle hash. The encrypted local approved copy is the sole source for Gym export.

## Live task harness

`npm run test:live -- --provider openai|anthropic|google [--model id] "task"` is opt-in, **paid and real**: it drives this Mac's desktop through the locally built native controller (`native/bin`), the Node HTTP provider adapter and the production `Runner` until the task settles. Build the helpers first, keep keys in `.env`, and watch the screen. Caps default to `--max-cost 0.25`, `--max-actions 30` and `--max-seconds 240`. Approval prompts are declined automatically; `--approve-routine` approves those whose reason lacks send/delete/pay/purchase/publish/install/password/security. Any pause or takeover stops the run, since nobody can say continue. Output is JSON event lines (no typed text or screenshots) and a summary in `output/qa/live-task-<timestamp>.json`. `--trace-dir <dir>` writes every screenshot, model observation summary, proposed action and native surface to that directory (mode 0700/0600); it contains screen content, so put it outside the repository and delete it afterwards. Harness results are not packaged-app or voice results.

`--memory [--memory-dir <dir>]` gives the harness the production memory layer: an encrypted `MemoryStore` in the directory (default: the OS temp folder) with a random key kept beside it, plus the native `index` method for recall. Use a scratch directory, never a real profile. Event lines add `memory` (recalled counts and plan), `replay` (plan steps, abandon reason, completion without a model call) and the summary adds `memory.planSteps`, `planAbandoned` and `planCompleted`. Running the same task again with the same directory shows learning: a built-in intent replays on the first run; a learned skill is a hint after one success and replays after two.

## Memory, system index and `open_file`

The design is in [MEMORY.md](MEMORY.md). Code lives in `src/memory` (store, retrieval, intents, skills, learning, access), the contract the runner is written against (`MemoryAccess`, `Recall`, `ReplayPlan`, `PlanStep`, `TrajectoryStep`, `LearnInput`, `SystemIndex`) in `src/core/memory.ts`, the replay executor in `src/core/runner.ts`, `openFileDecision` in `src/core/policy.ts`, and native index and file rules in `native/macos/Controller.swift` and `FileSafety.swift`. Tests: `tests/memory.test.ts`, `tests/runner-memory.test.ts` and `tests/native/FileSafetyTests.swift` (run by `npm run test:native-safety`). Rules to keep:

- Learned pointer steps store the control role and label (cut to the native 80-unit limit), never coordinates. Learning and replay share `normalizeLabel`, `normalizeRole`, `labelMatches`, `utf16Prefix`, `CONTROL_LABEL_LIMIT` and `REPLAYABLE_ROLES` from `src/core/labels.ts`, so change matching rules only there; a mismatch silently stops learned skills from replaying.
- A replayed step must go through `validateAction`, `controller.surface`, `evaluate`, approval and native execute exactly like a model action. Never add a fast path that skips one of them.
- File exclusions exist twice: the native index filter and the native `open_file` resolution share `FileSafety.swift`. Add a test to `FileSafetyTests.swift` for every new rule.
- The model sees memory only through `memoryForModel` in `src/providers/http.ts`, which enforces the context bounds. Keep memory out of plain diagnostics (counts and codes only) and replace `open_file` paths with `<FILE>` in contribution bundles and Gym exports.

The native permission/actuation matrix and live providers require dedicated manual/sandbox fixtures and credentials. Keep those test results separate from scripted tutorial results. `output/qa/` contains UI QA screenshots from the current work session.

## Add an app playbook entry

`src/providers/playbooks.ts` is the static table of keyboard routes the model gets as `context.playbook` for the frontmost application (design in [MEMORY.md](MEMORY.md)). To add an application:

1. Add its **lowercased bundle id** as a key in `playbooks` (`mdls -name kMDItemCFBundleIdentifier /Applications/X.app`, or read it from a run's `appId`). Add its display name to `names` only when frames for that app can arrive without a bundle id.
2. Write at most 6 lines, each at most 120 characters, ending with a period: how to search or open its command palette, how to create something, how to move through results, and the one thing to avoid (a destructive shortcut, a blind click, a needless `open_app`). Write them as imperatives the model can execute, naming exact chords.
3. Use only keys the action schema can send (`supportedKeys` in `src/core/schema.ts`): letters, digits, arrows, `ENTER`, `TAB`, `ESC`, `SPACE`, `PAGEUP`/`PAGEDOWN` and the CMD/CTRL/ALT/SHIFT modifiers. There is no way to press a backtick, comma or plus, so never suggest one. `tests/playbooks.test.ts` fails on a chord the model could not send.
4. Keep it data: fixed text only, no user content, no template, no code, no new action type. If a whole family of apps behaves alike, extend `categoryPlaybooks` and the `categories` patterns instead of adding one entry per app; a terminal-like app gets the shared "not allowed" lines, because the policy refuses those surfaces.
5. Extend `tests/playbooks.test.ts`: the bounds and key checks run over every entry automatically, so add the app to the covered list and assert the route you care about.

The provider injects the lines in `buildRequest` (`src/providers/http.ts`) as `context.playbook` inside the per-request JSON. Never move them into the system instruction: it is the cached prefix, and a per-app string there would invalidate the prompt cache on every app switch. A recalled **skill** plan suppresses the playbook (the learned steps already work for that task); a built-in intent does not.

## No-progress advice

`src/core/runner.ts` compares each new observation with the screen the last executed action ran on (`progressProbe`/`sameProbe`: app id, window title, frame `sha256`, focused element and control count, all fields it already has). Two actions of the same type in a row that change none of them append `noProgressWarning` to the last history entry and record `NoProgressDetected`. Keep it advice: it must never abort a run, never skip policy, never fire when the screen changed, and never appear more than once per stall. It resets when the screen changes, when the action type changes and in `resetLoop` (pause, correction, takeover, amend). Tests: `tests/runner-progress.test.ts`.

## The done audit's evidence rule

The done audit (`src/core/done-audit.ts`, docs/BENCHMARK.md "The done audit") reads the objective's requirements against the run's history lines and the screen at the claim by one text call to the run's own model, and what its prompt counts as evidence decides whether a correct run stands. Each rule in `DONE_AUDIT_PROMPT` came from a cycle that failed a correct run without it: a tool result reporting a file created, appended, replaced, renamed or moved is that file saved, so the tool route needs no save step (abc24ae, research-below-fold-fact #3); a clause that only names where or how ("open the file in TextEdit", "in Safari") is a means, met when the outcome it serves is met by a tool result or on screen, while a clause that is itself an outcome the user wants (a file opened for them to read) stays a requirement (55e4e83, dictate-paragraph-punctuation #1, `unmetKinds ["open"]` on both audits over a pass); a clause that forbids something ("don't do anything else with it") is met when no step did it, `met: true` with `evidence: null` (55e4e83, mail-draft-reply #2); a clicked control whose name is the action asked for (Keep draft, Apply, Save) and an app or file a step opened are evidence like a typed value. The prompt asks for at most `DONE_AUDIT_MAX_REQUIREMENTS` (12) requirements, `text` in a few words and `evidence` the number of the step that met it (a short string is accepted, never rejected; nothing reads it), and the reply has `DONE_AUDIT_MAX_OUTPUT_TOKENS` (4,000) output tokens: a requirement with a sentence of evidence is about 90 tokens, twelve about 1,080, and a reasoning model's thinking counts against the cap on OpenAI and Gemini; at 700 the cycle at 55e4e83 (the first with `kind` in the shape) cut six of fourteen replies at exactly the cap, two runs on both attempts, whose false dones then stood as `unavailable` — 4 unavailable in 15 audits against 1 in 17 and 1 in 13 the two cycles before. An empty `requirements` list is an unusable reply (one retry with `DONE_AUDIT_REMINDER`, then `unavailable`), never all met. The prompt is text the model reads, so the tests pin its sentences and length (`tests/runner-done.test.ts`, "the done audit's pieces"); only a cycle shows whether gpt-5.4-mini follows them.

## Optional hands-free voice

The saved `handsFree` setting defaults to false, including legacy encrypted configurations. Enabling it configures the native voice helper; the menu-bar toggle can disable capture even during a run. `WakePolicy.swift` anchors “Hey Butler” / “Hey Butler” at utterance start and determines silence/empty-command timeouts. `Voice.swift` retains background transcription inside the helper and emits neither text nor levels until activation. Each recognition generation invalidates stale callbacks on cancel, mute, restart and sleep. Standby sessions rotate at 45 seconds; nonempty final recognition normally supplies the command; an empty final after the explicit endpoint preserves the latest nonempty hypothesis as a separately marked recovered command. Wake detection signals the same native stop latch as push-to-talk and binds the same pending approval. macOS permission descriptions cover the optional always-active microphone. Diagnostics add only wake-state booleans/events; no ambient text or audio.

This local implementation reuses Apple Speech with `supportsOnDeviceRecognition` checked and `requiresOnDeviceRecognition` set. It has no backend, added speech API charges, custom wake model, or speaker verification. Apple reference: https://developer.apple.com/documentation/speech/sfspeechrecognizer/supportsondevicerecognition. Dedicated low-power keyword detection and measured false-wake/battery testing remain follow-ups.

Routine vs gated policy (`src/core/policy.ts`). Protected surfaces (uninstallers, the built-in floor, secure input, configured apps/domains) and credential/clipboard rules are checked first. Routine (`ALLOW`): `open_app` for a resolved, unprotected app; move/scroll; Escape and navigation keys; Command-Space/Tab/Shift-Tab, Command-F, a fixed set of application shortcuts (Command-W/T/N/S/Z/O/P, tab and arrow chords), browser Command-L/Command-R; focusing a text field; single-line typing, Backspace/Delete and Space in a known field; multi-line typing and Enter in a document app's text area (Notes, TextEdit, Pages, Word, Mail, Stickies); Enter in a verified browser address bar, a search field or a Spotlight field whose selection matches the query; Calculator keypad typing, digit/Enter/Backspace/Delete keys and named keypad buttons in `com.apple.calculator` when no sheet or dialog is open; menu-bar titles, tabs, context menus, selection/navigation roles and labelled content (including `AXHeading`); http(s) links to unprotected hosts; activatable controls with an allow-listed benign label; labelled `AXButton`/`AXRadioButton` inside a browser page whose own host is a Google, Bing, DuckDuckGo, Brave Search, Ecosia or Yahoo results host (native `targetWebHost` must equal the window domain), after the consequential-word check. Gated (`CONFIRM`): consequential words (send, delete, pay, install, save, …), any other labelled button/menu item/checkbox/radio button, shortcuts with Enter/Backspace/Delete, Command-Q, non-browser Command-R, Finder open/run gestures, line breaks or tabs outside document text areas, Enter/Space on an unknown control and links to protected hosts. `RETRY` (no input): unidentified or unlabelled targets, unverified shortcuts or keys, Dock application clicks (redirected to `open_app`), unresolved/ambiguous app names, mismatched Spotlight selections, and in a run pinned to a browser (`StartOptions.browser`, set by the bench for a task that names one; `Run.browser`, `PolicyContext.browser`) an `open_app`, or an `open_file` naming an application, that resolves to another browser on the fixed list (`BROWSER_PINNED`: "This task runs in Safari; open Safari instead." — a floor, so autonomy never relaxes it; a denial keeps precedence). A pinned run's `open_url` is sent to that browser by bundle id on either route (the `openUrl` hook, or LaunchServices `open -b` in the bench's controller), never to the browser in front or the most-used one; cycle `20260920-0415` `home-dashboard-lights` #1 opened the person's Chrome with Safari named, and the address and six clicks followed it there. On a blind surface (`Surface.accessibility === "none"`) only, an unidentified pointer target and typing with no identified field become `CONFIRM` instead, and the application's own search chords (Command-K, Command-L) become routine; see "Blind surfaces" below. `DENY`: detected credentials, clipboard chords, uninstaller controls, installer launches, protected launches, executable/local-file URLs and Command-L outside a browser. Decision reasons are included in the local diagnostic stream.

Local task replay: `npm run debug:local -- --hands-free --command "Open Notes"` submits through the same command, policy, budget and cancellation paths as voice. It uses LaunchServices to preserve microphone permission attribution. An already running instance receives the command without opening Settings. Task text remains in the encrypted run journal, not the diagnostic stream.

Each model observation carries the exact successful action arguments (without obsolete frame IDs) and the current macOS app identifier. Single-key hotkeys normalize to ordinary keys before policy evaluation. The native controller identifies Spotlight only when its search panel is visibly present and its accessibility text field owns focus. Captures wait up to 250 ms for the app to process the preceding generated input; cancellation stays active. A one-use, 150 ms exception recognizes only the matching Command-Space event forwarded by the system Siri executable. Physical input, other keys/modifiers, other processes and expired events still trigger takeover.

Spotlight Enter is permitted only when the AX-selected result matches the nonempty query exactly or after dropping vendor/qualifier words and version numbers (“Chrome” → “Google Chrome”; extra product words never match); installer/destructive selections are denied. The model receives `context.launcher.query` and `selectedResult`. Selected-result changes invalidate the native frame. Uninstaller processes require manual takeover before capture or input. Pointer targets labelled Uninstall are denied. The system prompt prefers `open_app` and treats Spotlight as a fallback. This guard does not establish general semantic task correctness.

Second-instance launches transmit original argument pairs with Electron `additionalData`; Chromium-reordered argv must not be used to extract a command. The packaged desktop test submits Stop from a real second process and verifies cancellation with no task correction. Reference: https://www.electronjs.org/docs/latest/api/app#event-second-instance.

Navigation/input revalidation: OS navigation, browser Command-L and `open_app` verify the original window, display, protected-surface state and stop latch without requiring unrelated content pixels to freeze. Text editing verifies the exact focused AX element, role, label, value, selection range, enabled state and bounds. Browser-address Enter requires a native toolbar field outside any AXWebArea; form-field Enter outside search fields keeps confirmation. Browser address text is bounded/redacted in model context and omitted from plain diagnostic logs. The frame context's `browserAddress` (`ScreenContext.browserAddress`, 2,000 characters; what `web__read_current_page` reads as `ToolWords.pageAddress` and what `PAGE_TOOL_NOTE` keys on) is the page's own URL whole, read from the web area holding focus, else the window's first web area naming a host, else the window's document URL (`pageAddressCandidates` in `native/macos/Controller.swift`, the walk `pageIdentity` shares), and the address field's text only when that field is focused and no page URL was read (`browserPageAddress` in `native/macos/InputSafety.swift`; until 2026-09-20 the focused field was the only source, so a page with focus in its content reported no address and the tool was refused `no_page` on every research page of cycles 20260920-0327 and 20260920-0415); `addressBar` still says the field is focused, the same is reported for a browser's bound window, and `FrameCaptured` never carries the address. Executable/local-file address and link schemes are denied. Unknown clicks trigger bounded recovery without execution; consequential actions retain approval and full revalidation.

A browser-only Command-L proposed in a non-browser application is rejected with switch-app guidance, rather than asking the user to approve an unrelated shortcut. Successful execution resets the consecutive invalid/denied-action counter; cost/time/action budgets still bound the whole run.

Automatic re-aim (screen-change recovery): on an animating page a click lands about 3 s after the screenshot it was based on (medians measured on this Mac: capture 504 ms, model call 2052 ms, execute 492 ms), and native input then refuses it with `STATE_CHANGED` before anything is sent. When that happens to a model-proposed pointer action, `Runner.reaim` in `src/core/runner.ts` captures a fresh frame itself and looks for the same control in `context.controls` by accessibility role and normalized label, with `labelMatches`, `normalizeRole` and `normalizeLabel` from `src/core/labels.ts` — the rules skill replay already uses. Exactly one enabled match re-proposes the same action at its new position with the fresh frame id, and the whole pipeline runs again for it: `validateAction`, `controller.surface(action)`, `evaluate`, approval if the policy now asks for one, native `revalidate` and `execute`. It stays the same step: no model call, no usage, one counted action. Limits: at most one re-aim per model-proposed action; only `click`, `double_click`, `right_click` and `move`, never `drag` (two endpoints and a path do not translate); never a replayed plan step (those resolve their own labels every frame); never when the policy decision was `CONFIRM`, so an answered approval is never reused — the model proposes again and the user is asked again; never after a pause, correction, takeover or stop (the runner's epoch and hands-on flag must be unchanged, checked before and after the fresh capture); and never when the target was never identified (no role or label on the action surface), when zero or several controls match, or when the fresh frame's `appId` differs from the surface the action was aimed at. Any failure, including a blocked or failing capture, falls back to today's behavior: `ActionFailed STATE_CHANGED`, the rejected-step history entry and a new model call, with the third consecutive rejection still pausing the run. The executed step's history entry ends with the re-aim note, so the model's next observation says the screen moved and the app re-aimed at the same control. The journal records a content-free `ActionReaimed {actionType}`; `scripts/analyze-runs.mjs` classifies it as `ACTION_REAIMED` and prints a "recovered without a model call" line under the friction table. No native or policy code changed: the re-aim re-enters the pipeline instead of re-pointing input, so every freshness, protected-surface and hit-test check still runs on the new coordinates. Re-reading the target position natively just before input was considered and rejected: native `execute` already re-reads surface, window and pixels through `revalidate`, and moving the coordinates there would send input at a point the policy never evaluated and the user never approved, while a rejection carries no control payload back to the runner. Tests: `tests/runner-resilience.test.ts` ("automatic re-aim after a screen change").

Unidentified target recovery: the policy returns `RETRY` for an unrecognized click, unlabelled control, unverified key/shortcut or unresolved app name. The runner sends no input, records `ActionRetargetRequested`, and gives the model fresh context plus the reason. Three consecutive retries hand over to the user, with no generic approval popup. Successful input resets the count. Diagnostic events include action type, foreground app, AX roles and launcher status, never control labels or field contents.

Blind surfaces (applications that publish no accessibility): some Chromium/CEF applications (Spotify) and custom-drawn windows expose a window and nothing inside it, so `AXManualAccessibility` does not help and every observation returns no focused element, no `context.controls` and no hit-test target. `surfaceAccessibility` in `native/macos/InputSafety.swift` is the pure rule and `accessibilityLevel` in `Controller.swift` feeds it: a verdict of `none` needs Accessibility trusted, a frontmost window of at least 200x120, a completed bounded walk (`actionableWalk`, first actionable role wins, 600 nodes / 120 ms / depth 12) that found nothing, no usable focused role (`AXWindow`, `AXApplication`, `AXGroup`, `AXUnknown` and an empty role identify nothing) and no hit-test target for this action. Anything else is `partial`, a focused element with controls is `full`, and an untrusted process or a missing/too-small window gets no field at all, so a loading window or an empty desktop is never called blind. The value is reported as `Surface.accessibility` (with `Surface.appName` for the approval text) and as `context.accessibility`; every surface also carries `context.menus`, the application's own menus as one line each with their shortcuts (at most 12 menus of at most 14 items), because AppKit builds the menu bar from the application's own `NSMenu` and it stays in the accessibility tree when the window content does not; in a blind application that map plus `menu_item` is the whole route, and the live failure it fixes is Spotify with no open window, where every shortcut is a no-op and `Edit > Search` is greyed out until `Window > Spotify` restores the window. In `evaluate`, `blindSurface` gates three changes and nothing else: an unidentified pointer target becomes `CONFIRM` ("Click here in Spotify? I can't see its controls.", likewise Double-click and Right-click), `type_text` with no identified field becomes `CONFIRM` ("Type here in Spotify? I can't see its text fields.", never quoting the text), and Command-K/Command-L become routine as the application's own search. Protected apps, secure input and uninstallers still take over first, installer/setup/updater names are denied, credential text is denied, and an application that does expose controls keeps the unchanged `RETRY`. The instruction tells the model to stop repeating `open_app` for the frontmost application, drive the app by shortcut and menu bar, spend at most one approved click on reaching a text field, and say what it did in `done`. Tests: `tests/policy-routine.test.ts`, `tests/providers.test.ts`, `tests/context.test.ts` and `tests/native/FrameSafetyTests.swift`.

`open_app`: the model names an application; the native helper resolves it (see [architecture](ARCHITECTURE.md)) during `surface(action)`, binds the verified bundle to that frame, and at execute re-resolves the name and re-reads the bundle before activating a running app or launching it through LaunchServices (a running app with a visible window may be reopened once if activation stalls). A running app that comes to the front with no window (none on screen after a 1 s settle, `windowCountSettled` in `LaunchSafety.swift`, so an unhidden window or a Space switch is not mistaken for none) is never reopened (a windowless document app answers that with an Open panel); the helper presses the item in its own Window menu that names its main window and waits briefly for it. `mainWindowMenuEntry` in `NamedTargets.swift` takes only the application's exact name or a main-window title confirmed for that bundle (Mail's Message Viewer), never a window command or a `menu_item` refusal, and reads only up to Bring All to Front, because AppKit lists the application's windows after it under their own titles; a menu without that item is not used. The element it approves is the one pressed, and one that reads greyed out is checked again with the menu open. The result reports app ID, frontmost, whether it was already running and, for a running app, its window count and whether the Window menu restored one; the history tells the model to verify `appId`, or that the app shows no window and to use its Window menu or File > New rather than open it again. `context.windowCount` gives the model the same count on each frame (not for Spotlight's panel), and policy lets `open_app` of the frontmost app through only while `surface(action)` reports 0 windows. Name rules live in `native/macos/LaunchSafety.swift` and are mirrored by `INSTALLER_PATTERN` and the protected floor in `policy.ts`; change both together. Dock application clicks are still verified natively (`com.apple.dock`, `AXApplicationDockItem`, bundle identifier) but return `RETRY` redirecting to `open_app` (on the frontmost app's own icon while it shows no window, the reason names its Window menu and File > New instead); a second `open_app` of the app the last executed `open_app` left windowless is `RETRY` in the runner until another step executes, so repeats reach the three-retry hand-off; installers and protected apps are denied or taken over. Focusing a text field is classified separately from activating a Send/Delete button.

Voice hold: holding the shortcut or a wake phrase pauses a working run (an approval stays pending). Stop and pause intents are routed only from the final transcript, because a partial “Stop” is often the start of a longer correction. A final command becomes a same-run correction; an unrecognized or empty result keeps the run paused with “Didn’t catch that.” Only dismissing an untouched text-entry pill that a tap opened while the run was working resumes it automatically; any takeover, helper restart, correction or later event makes the pause the user's. Turning the microphone off neither pauses nor resumes a run.

GPT-5.4 mini requests now explicitly use `reasoning.effort: low` and a 4,096 output-token ceiling; other model IDs retain their previous request shape. This keeps the selected model and allows recovery from rejected actions, while reasoning tokens count toward cost. OpenAI documents `none` as the mini default and `low` as supported: https://developers.openai.com/api/docs/models/gpt-5.4-mini . This configuration is not a guarantee of better task completion.
