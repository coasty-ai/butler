# Open Assist build summary

Snapshot: September 16, 2026.

Open Assist is a working macOS development alpha with real voice input, screen observation and mouse/keyboard control. The product foundation is implemented and packaged locally. Reliable completion of everyday desktop tasks is still the main unresolved problem; the current build is not ready to promise the intended effortless daily experience.

| Area                            | Built so far                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Mac application                 | Electron/React/TypeScript shell with two native Swift helpers. Apple Silicon `.app` at `release/mac-arm64/Open Assist.app`. Menu-bar “Assist” entry, small settings window and floating status pill.                                                                                                                                                                                          |
| Appearance                      | Monochrome interface, bundled Space Grotesk, custom orbital icon, audio-reactive listening indicator, rotating working rings, approval pulse and completion fade. Reduced-motion support.                                                                                                                                                                                                     |
| Voice interaction               | Hold Option+Space to talk, release to execute; tap for text. Optional Siri-style “Hey Assist” activation is implemented and enabled for the local testing session. Apple on-device speech recognition; no cloud audio fallback.                                                                                                                                                               |
| Screen context                  | Screenshots, foreground app/window, accessibility text and selection where available, up to 60 grounded controls with screen positions (including browser page controls), bounded recent window/document/task references. Verified Chrome/Safari-style address-bar context and Spotlight selected-result context.                                                                             |
| Computer control                | Actual clicks, double/right clicks, movement, dragging, scrolling, text entry, keys and modifier chords. Observe → propose → validate → execute → observe loop, with completion checking, task budgets, loop/app-switch detection and recovery from malformed output, provider outages and helper restarts. A launch-only `open_app` action opens allow-listed installed apps. No shell tool. |
| Interruption                    | Pause on shortcut activation or manual mouse/keyboard input; Escape/emergency stop; voice corrections extend the current run. Cancellation invalidates late model responses.                                                                                                                                                                                                                  |
| Approval and protection         | Routine recognized navigation/editing and benign-labelled controls proceed automatically. Consequential and other labelled controls require approval; unidentified targets retry up to three times before pausing for help. Approval is tied to the proposed action and current state; protected surfaces, installers and a built-in protected app floor are blocked.                         |
| Models                          | Adapters for OpenAI, Anthropic, Gemini, OpenAI-compatible APIs and Ollama. Local testing currently uses `gpt-5.4-mini`. Keys from `.env` are imported into encrypted local storage. Vendor-native computer-use tools are not integrated; adapters use our own visual GUI-action schema.                                                                                                       |
| Local records                   | Encrypted task trajectories and screenshots, correction/takeover events, per-run deletion and OS-protected key storage.                                                                                                                                                                                                                                                                       |
| Diagnostics                     | Local rotating JSONL stream with action/state events, provider/native timings, retries, usage and redacted errors. Full task content stays in encrypted history. Logs support active debugging; they do not create a continuously running autonomous debugger.                                                                                                                                |
| CoArena contribution groundwork | Per-run review, exclusions, explicit consent, resumable upload, checksums, receipt and withdrawal. Local encrypted quarantine service with expiry. Native screenshots are excluded from contribution in this alpha.                                                                                                                                                                           |
| CoArena Gym groundwork          | Approved-workflow export, a deterministic seeded task-board fixture and grader. A starter implementation, not a production environment/evaluation platform.                                                                                                                                                                                                                                   |

Recent debugging addressed provider connection recovery, misleading generic errors, stale approval geometry comparisons, Spotlight focus, Siri shortcut forwarding, manual takeover detection, wake-command segmentation and second-instance Stop delivery.

The latest approval failure was traced to a playing video changing unrelated window pixels while Chrome's address bar was focused. Keyboard validation now checks the relevant input target, value and selection rather than rejecting edits solely because background video changed. Verified address-bar navigation no longer requests routine approval. These fixes passed targeted tests, but the complete YouTube task has not yet succeeded: the model still makes incorrect app/target choices and can trigger another unknown-control approval. The approval experience is therefore improved in specific cases, not resolved end to end.

Recorded validation:

- Latest recorded counts (before the final orchestrator changes; final sweep being re-run): 485 TypeScript unit/integration tests, 190 native Swift checks, 3 browser flows, 18 desktop smoke checks and 24 native input checks.
- Terminal live harness (GPT-5.4 mini, source helper, not the packaged app): Calculator 128 × 46 correct in 5 actions after earlier failures (including one wrong reported result); Safari web search in 3 actions; Safari + Calculator °F → °C correct in 19 actions after earlier failures.
- Successful production builds; browser preview and packaged Electron integration checks have also passed.
- Live “Open Notes” completed through actual Mac input after resuming from a manual takeover, with three executed actions and no approval prompts.
- A generated-screen OpenAI task passed; another packaged model fixture failed despite healthy connectivity. Anthropic task checks failed, and Gemini inference was blocked by the key's API restrictions.
- No successful end-to-end “open YouTube and play a Weeknd song” result. That earlier diagnostic snapshot was waiting for approval before executing an action.

For local testing, no hosted backend, account service, cloud database or GPU server is required. The Mac runs the app, voice pipeline, controller and storage. Cloud reasoning goes directly to the selected provider with the user's key; fully local reasoning requires a separately installed Ollama vision model and has not been validated for desktop reliability. Source builds require Node 22.12+ and Xcode Command Line Tools; the packaged app does not require Node. macOS screen/input/microphone/speech permissions remain necessary.

The packaged app in `release/mac-arm64` has not been rebuilt with the latest change set. The immediate remaining work is reliable model action selection (especially multi-app planning), fewer unnecessary approvals, successful repeated real-world task runs, and measured speech/interruption latency. Broader device and permission testing, signing/notarization and signed updates are required before distribution. Optional spoken TTS, a comprehensive recent-files index, Windows/Linux control and production contribution/Gym infrastructure are not built.
