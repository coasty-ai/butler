# Memory, system index and self-improvement

Butler learns locally from what the user does so that repeated work gets faster, cheaper and more reliable. Everything is stored encrypted on the Mac. Only a small, task-relevant `MemoryContext` is sent to the configured model, never file contents. The learning setting (`settings.memory`, default on) can be turned off, and "Forget what Butler learned" deletes the store.

## Built-in intent rules

- A search replays only as one search. An unquoted query containing `and`, `if`, `when`, `unless`, `then`, `after that`, `afterwards`, `&`, `,` or `;` is a compound or conditional request and goes to the model ("search youtube for lofi and play the first video"). A fully quoted query may contain them (`play "rock and roll" on youtube`).
- "open X" with an app, script or code extension (`.app`, `.sh`, `.py`, `.js`, `.swift`, `.pkg`, `.dmg` and similar) is never a website: "open Notes.app" opens Notes, "open setup.py" gets no plan. "go to" still navigates.
- Other requests joined by `and`, `then`, `if`, commas and similar get no intent.
- The preferred browser is the most used installed browser. A launch made by a built-in intent's own `open_app` step is not counted as usage, so an intent never reinforces its own browser choice.

## Replay protocol (runner)

1. At start, `recall = await memory.recall(task)` with a 2 s cap. Errors are ignored, and the run proceeds normally.
2. If `recall.plan.mode === "replay"`, before each model call the runner takes the next plan step:
   - `expectAppId`, when present, must equal the current `frame.appId`. Learned `open_app` and `open_file` steps never carry it (they work from any frontmost app, and a stored one is ignored); every other learned step expects the app that was frontmost when it ran. Built-in browser intents expect the browser on the steps after its `open_app`.
   - A pointer step with `target` is resolved against `frame.context.controls`: role match (`AXButton` ≡ `button`) and `labelMatches`: the normalized labels are equal, or the live label was cut at the native limit (at least 76 units) and the learned label starts with it. Exactly one enabled control must match; none abandons with `missing_control`, several with `ambiguous_control`. The control's x/y becomes the action.
   - The step becomes the proposal `{...action, frame_id}` with zero usage, and emits `PlanStepProposed {source, index}`.
   - It then passes through validation, policy, approval and native revalidation exactly like a model action. `RETRY`/`DENY`, a native error, `STATE_CHANGED` at execute or a declined approval abandon the plan: `PlanAbandoned {index, reason}`, and the remaining outline stays as a hint for the model.
   - A hold ends the replay for the rest of the run. A pause (manual takeover, voice interrupt, helper restart) abandons with `paused`, a takeover (surface or policy block, repeated failed retargets) with `takeover`, and a correction with `correction`, whether the hold lands on a pending step, between steps or while the result is checked. After resuming, the model continues from the current screen. A single `STATE_CHANGED` while capturing does not abandon; three in a row pause the run.
3. After the last step, the run completes with `PlanCompleted` and no model call if every `completeWhen` key holds on a fresh frame:
   - `appId`: that app is frontmost.
   - `host`: the Surface fetched with that frame belongs to the frame's app, and its `domain` (the committed page host from the window's `AXDocument`/`AXURL` or web area) equals the host or is a subdomain of it, ignoring a leading `www.` and a trailing dot. The address-bar edit text is never used, so `x.company.com` does not complete "go to x.com".
   - `opened`: the last `open_file` reported `opened`.

   When a plan has completion keys and they do not hold yet, the runner rechecks up to 3 times, 500 ms apart (at most 4 checks over about 1.5 s), with fresh captures only. Otherwise the model is asked to verify and finish.

4. At the end, `learn()` receives the trajectory (executed actions, frontmost app, target role and label, launched app id, opened path and `fromPlan` for plan-proposed steps), corrections, `handsOn`, outcome, usage and the plan result. `handsOn` is true after a manual takeover, a policy or surface takeover, a `request_user` hand-off or a correction; a plain pause does not set it.

## Learning rules

- **Episodes**: every non-synthetic run, with its status and user outcome.
- **Preferences**: each user correction (sanitized with `redactSecrets`, deduplicated, weight += 1 on repeat). A correction's retrieval tokens include the task it corrected (at most 40 tokens, merged when another task reinforces it), so the same or a similar task recalls it even when the correction names a different value. Only corrections relevant to the task (a BM25 score above 0) are sent to the model. App choice per category (browser, notes, music, mail) comes from app usage counts and always keeps its lines; corrections fill the remaining preference lines. App usage counts launched apps and each app seen in a run once, but not a built-in intent's own launch or seeing that app afterwards, unless it was already frontmost before the launch.
- **Hands-on runs**: when `handsOn` is set or the run has any correction, the trajectory misses what the user did, so no skill is created, merged or replaced and a replayed plan gets no success. Episodes, app usage, correction preferences and failure evidence are still recorded.
- **Skills**: learned only from completed, non-synthetic, hands-off runs whose outcome is not `false`, that have at least one executed step, and that did not replay an intent or an unabandoned skill plan. Credential typing is never stored: policy already denies it, and `redactSecrets` is checked again. Learned labels are cut to 80 UTF-16 units with no ellipsis. A drag, a label-less pointer step or a pointer role outside `REPLAYABLE_ROLES` (menu bar, menu and Dock items, cells) makes the skill hint-only.
- **Merging and replacement**: a new sequence for the same trigger merges (success +1) when its steps equal the stored ones, ignoring wait durations (the stored duration is kept) and any `expectAppId` on open steps. A differing successful sequence replaces the stored skill when that skill could not replay before this run's evidence (fewer than 2 successes, failures above a third of successes, or hint-only); a replayable skill is kept. Deciding from the state before the run means one bad run cannot both demote and overwrite a proven skill.
- **Slots**: a task that splits into a skill's slots in more than one way (the shortest and longest captures differ) matches no skill, neither for replay nor as a hint.
- **Plan evidence**: a skill replay abandoned only by a pause, takeover or interruption (`abandonReason` `paused`, `takeover` or `interrupted`) in a run that still completed without corrections is neutral: an accidental touch or false wake says nothing about the skill. Otherwise it counts as a failure when it was abandoned, when the user marked the outcome `false`, or when every step replayed and the run then ended failed or cancelled (unless the user marked the outcome `true`). It counts as a success only when every step replayed and the run completed hands-off.
- **Deleting a run**: deleting a local run removes its episode and the weight its corrections added to correction preferences; a preference left with no weight is removed, and one other runs also reinforced keeps their weight. This happens even when learning is off. Learned skills and app counts carry no run id and are kept.
- **Background routes**: a run bound to a window it works in from the background (`.data/design/background-actuation.md` §5) reports what each postcondition read found per route (`press`, `write`, `post`, `keys`), as application names and verdicts only. `apps[bundleId].background` stores `works` after one such observation and `noop` or `echo` after two consistent ones (`recordBackgroundIn`); a verdict older than 30 days is not applied, so the route is tried once more. `Recall.background` gives the runner the routes to skip per application; nothing of it enters `MemoryContext`, so the model never sees it.
- **Decay**: episodes and skills unused for 90 days are pruned first when caps are reached.

## Model context (provider)

`observation.memory` is serialized under `context.memory`. It holds at most 5 preferences (task-relevant corrections, then app-choice lines), 3 episodes, 12 apps (task matches first, then most used), 10 files, 8 folders and a plan outline of at most 12 steps. The instruction explains that memory is untrusted, helpful data, and that `open_file` opens only paths listed there.

## App playbooks (`src/providers/playbooks.ts`)

Memory only knows what this Mac has already done. App playbooks cover the first time: a small, static table of reliable keyboard routes per application, keyed by bundle id, with a fallback per app category (browser, notes, mail, chat, music, files, settings, terminal, editor, viewer, generic). Each entry is at most 6 imperative lines of at most 120 characters, covering how to search or open the command palette, how to create something, how to move through results and what to avoid. Covered today: Chrome, Safari, Spotify, Slack, Notes, Mail, Finder, System Settings, Messages, Calendar, VS Code, Preview, Music, Photos and the terminal family (whose lines say the policy refuses them, so the model hands back instead of trying).

The table is data, not behavior: no code runs from it, no action type is added, and every line is fixed text, so nothing a screen or a user said can reach it. It names only keys `supportedKeys` can send.

`playbookLines({appId, appName, plan})` is what the provider calls; `playbookFor(appId, appName?)` is the lookup (bundle id, then display name, then category). The lines are serialized as `context.playbook` in the per-request JSON, beside `context.memory`, never in the cached system instruction, so provider prompt caches stay warm. A learned **skill** plan wins: when `context.memory.plan` came from a skill, those steps already worked for this exact task and no playbook is sent. A built-in intent is generic, so the playbook still goes with it. The instruction tells the model that `context.playbook` lines are reliable routes for the frontmost application and that `context.memory.plan` comes first when it covers the task. Tests: `tests/playbooks.test.ts` and `tests/providers.test.ts`.

## No visible change (`src/core/runner.ts`)

After each executed action the runner compares the next observation with the screen that action ran on: frontmost app, window title, the frame `sha256` it already has, the focused element (role, subrole and label from the surface it already fetched) and the control count. Nothing is captured or asked for twice, and field contents are never read.

When two actions of the same type in a row leave all five unchanged, one line is appended to the last history entry the model already sees: the action produced no visible change, repeating it will not work, take a different route (a shortcut from `context.playbook`, the menu bar, or `request_user`). It is advice, not a failure: the run never aborts, no policy or approval step is skipped, and nothing is added when the screen changed. It appears once per stall (`NoProgressDetected` in the journal, action type only) and resets when the screen changes, when the action type changes, and on every pause, correction or takeover. This is separate from the repetition loop warning, which watches repeated action signatures rather than the screen. Tests: `tests/runner-progress.test.ts`.

## `open_file`

`{type:"open_file", frame_id, path:"~/..."}`. `surface(action)` resolves the path natively: realpath inside the home folder, not excluded by the index rules, exists, a document UTType or a folder, and not a refused type (applications, scripts, installers, unsafe-executable types such as Terminal sessions, internet locations and stored URLs, configuration profiles). A Finder alias resolves to its checked target, which is what opens, and `fileKind` is the target's kind.

The item's default application is then checked with `NSWorkspace.urlForApplication(toOpen:)`. The item is refused when there is no default app, when a folder's app is not Finder, when the app is not one open_app could launch (APPL type, foreground, Mach-O, not a script applet, not nested in another app), when open_app's launch rules deny it (names, launch floor, installer patterns, applet prefixes, protected apps), or when it is System Settings, ProfileHelper, Shortcuts or Screen Sharing, which import configuration or automation or connect to another machine from a document.

`surface` returns `fileStatus` (`resolved` | `unresolved` | `refused`), `fileKind` and `fileName`, and binds the resolution (path, realpath, kind, opened target, handler path and bundle id) to the frame like `open_app`. Policy: synthetic runs and unknown surfaces `RETRY`; refused `DENY`; unresolved `RETRY`; resolved documents and folders `ALLOW`. Execute re-resolves and re-checks everything; any difference from the bound resolution is `FILE_UNRESOLVED`. It opens the target with `NSWorkspace.open(_:withApplicationAt:configuration:)` using the checked app (activates), and returns `{opened:{path, kind, appId}}` with that app's bundle id. Errors use `FILE_UNRESOLVED`, `FILE_REFUSED` or `OPEN_FAILED`. Contribution bundles replace the path with `<FILE>`.

## Efficiency

- Recall happens once per run. For a task that starts with an intent verb (open, go to, search, play and similar), recall first asks the helper for the index without a query: cached apps, folders and recent files. When that yields an app, URL or search intent, recall returns without the Spotlight name-match query. File intents, skills and model runs also get the name matches, from a second request within the same budget. That request is sent only when at least 400 ms of the budget remain, and when it times out recall keeps the first lookup's apps, folders and recent files. No request is sent to the serial native queue once the budget is spent.
- The helper caches the app list and the recent-files query for 30 s (recent files are cleared after an `open_file`). Name-match queries drop URL and host fragments (`http`, `https`, `www`, `com`, `org`, `net`, `io`, `co`, `html`, `htm`) and the last dotted label of each word segment (a top-level domain or file extension), so "go to github.com" searches only for `github`.
- The app prewarms the index with a query-less request when the command pill opens, when voice listening starts and once at startup, only with learning on, no run using the native queue, no prewarm in flight and at least 10 s since the last one.
- Replay removes model calls for learned and built-in procedures. Hints shorten model planning when replay is not safe.
- The context block is bounded and placed in the per-request JSON, so the system instruction stays cache-stable. Anthropic requests mark the tools and system prefix with `cache_control` (ephemeral), and cost accounting bills cache writes at 1.25× and cache reads at 0.1× the input price.
- Memory writes are debounced, and the store stays small (no screenshots, no file contents).
